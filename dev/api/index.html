API reference

BrewQuiverTerm.BrewQuiverTerm — Module
BrewQuiverTerm

A terminal user interface for BrewQuiver, built with Term.jl on BrewQuiverUICore: the rendering functions take the view data of a session and return Term renderables, so that they are tested without a terminal; the interaction loop is thin.

source
BrewQuiverTerm.run — Function
BrewQuiverTerm.run(path = nothing; library = nothing, input = stdin, output = stdout, size = nothing)

The interactive app on the quiver saved at path, or on a BeerJSON recipe imported from it, or on a new quiver, with the ingredients of the BeerJSON documents library (a path or a vector of paths) to add. Press ? for the keys. On a terminal, it takes the alternate screen in raw mode, and gives it back when it quits; size = (height, width) overrides the size of the terminal. Returns the App when it quits (or when input ends).

source
BrewQuiverTerm.open_file — Function
open_file(path) -> Session

A session of the file at path: a quiver saved by BrewQuiver, or a BeerJSON document whose first recipe is imported.

Rendering

BrewQuiverTerm.render_overview — Function
render_overview(s::Session; width = 100)

The overview of the quiver of s: a panel for the lots (the nodes in no vessel), with their contents, and one for each vessel, in topological order, with the results of its nodes (volume, gravity, ABV, IBU, color, temperature, mash pH) and the arrows leaving them. The selected items are marked ▶, the nodes that changed in the last step ✱ and highlighted, the nodes with warnings ⚠.

source
BrewQuiverTerm.render_node — Function
render_node(s::Session, label; width = 80)

A node in detail: its results, its initial contents (for a lot), its contents and leftover in the brew (liquor, solids with their timing, water profile), the arrows arriving and leaving, and its warnings.

source
BrewQuiverTerm.render_arrow — Function
render_arrow(s::Session, ref::ArrowRef; width = 80)

An arrow in detail: its fields (those not given are taken from the equipment of the vessel, or defaults), its duration, and what it moved and released in the brew.

source
BrewQuiverTerm.render_statusbar — Function
render_statusbar(s::Session; width = 100)

One line: the file of the session (or "new quiver") with ● if it has unsaved changes, the state of the brew, the number of warnings, and the step undo would undo.

source
BrewQuiverTerm.render_history — Function
render_history(s::Session; width = 80)

The steps of the history of s, oldest first: those done (✓), which undo would undo from the last, and those undone (dim), which redo would redo from the first; the step whose state was saved is marked "saved", and the current state "◀ now".

source
BrewQuiverTerm.render_dag — Function
render_dag(s::Session; cell = 14)

A drawing of the quiver of s as a layered graph, from positions(s) (the nodeview positions, or the layout of BrewQuiverUICore): each layer a column cell characters wide, each node a dot of its color (○ for none) and its label, cut to fit; the arrows from left to right, routed in the gaps between the columns, passing behind the nodes on their way. The selected node is in reverse video, the nodes changed in the last step highlighted. Returns a block of text in Term markup.

With a width, only that many columns are drawn, around the node focus if given (a third of the way in), else from the left.

source
BrewQuiverTerm.render_timeline — Function
render_timeline(s::Session; width = 100, start = 0u"minute", zoom = 0)

The timeline of the brew of s (from start, e.g. 8u"hr"): a chart of when each vessel is busy, each node of the vessel a bar of its color from when it starts being filled to when it is emptied, over the first 1/2^zoom of the timeline (zoom in to see the brew day before a long fermentation); the vessels booked for two contents at once; and a table of when each node is filled, ready and emptied.

source
BrewQuiverTerm.render_solution — Function
render_solution(sol; width = 100)

A Solution of Solve: whether it converged and in how many iterations, the values of the parameters, and each target with its goal and what was reached.

source
BrewQuiverTerm.render_text — Function
render_text(x) -> String

The text of a renderable without its colors and styles (the ANSI codes), e.g. to test what a rendering function shows.

source
BrewQuiverTerm.clock — Function
clock(t)

A time of the timeline (a time quantity from its start) as a clock reading, as BrewQuiver writes them: "8:05", or "3d 14:20" after the first day.

source
BrewQuiverTerm.parse_solve — Function
parse_solve(text) -> Solve

The Solve command of what is typed: targets, then vary and the parameters, as many as the targets, separated by commas:

fermentor gravity 1.050 sg, wort ibu 30 IBU vary pale crystal, cascade

A target is a node, a quantity (gravity, og, volume, ibu, srm or color, abv, carbonation) and its goal; a parameter is lots scaled together (pale crystal, see Amount), or a field of an arrow, source>destination.field or source>destination#2.field (see Setting).

The app

BrewQuiverTerm.App — Type
App(session)

The state of the interactive app: the Session of BrewQuiverUICore being edited (whose selection is the cursor of the app), the Mode, the scroll of the main view, the last message, and whether to quit. Keys are given to handle!, frames drawn with render_app.

source
BrewQuiverTerm.handle! — Function
handle!(app::App, key)

What key (a Char or a Symbol, see decode_keys) does in the current mode of app. Errors a user can cause (a refused edit, a file that cannot be read) become the message of the app.

source
BrewQuiverTerm.render_app — Function
render_app(app::App; width = 100, height = 30) -> String

The frame of the app, height lines of width columns: the status bar, the main view of its mode (the overview, scrolled to keep the selection in view, the inspector, the help), the message or prompt line and the keys. It only changes the scroll of app.

source
BrewQuiverTerm.decode_keys — Function
decode_keys(input::AbstractString) -> Vector{Union{Char, Symbol}}

The keys typed in input, as read from a terminal in raw mode: printable characters as Chars, the others as Symbols (:up, :down, :left, :right, :enter, :esc, :tab, :backtab, :backspace, :delete, :home, :end, :pageup, :pagedown, :ctrl_c, :ctrl_s, :ctrl_y, :ctrl_z, :ctrl_o). Unknown sequences are dropped.

source
BrewQuiverTerm.Mode — Type
Mode

What the app is doing, which decides what the keys do: Browse the overview, Inspect the selected node or arrow, answer a Prompt or a Confirmation, read the Help.

source
BrewQuiverTerm.Browse — Type
Browse()

The overview of the quiver: the keys move the selection between the nodes and their arrows.

source
BrewQuiverTerm.Inspect — Type
Inspect()

The selected node or arrow in detail.

source
BrewQuiverTerm.Help — Type
Help(back)

The keys of the app; any key goes back to the previous mode.

source
BrewQuiverTerm.Prompt — Type
Prompt(question, buffer, submit, back)

A line of text to type, for question, starting with buffer: Enter calls submit(app, text), Esc goes back.

source
BrewQuiverTerm.Confirm — Type
Confirm(question, choices, back)

A question answered with a key: choices are key => (label, action), the action called as action(app); Esc goes back.

source
BrewQuiverTerm.HistoryView — Type
HistoryView(back)

The history of the edits; any key but the arrows goes back.

source
BrewQuiverTerm.DagView — Type
DagView()

The drawing of the quiver (see render_dag): the keys move the selection as in the overview; l arranges the nodes (the layout of BrewQuiverUICore, undoable).

source
BrewQuiverTerm.TimelineView — Type
TimelineView(back, zoom)

The timeline (see render_timeline): + and - zoom in and out on its start.

source
BrewQuiverTerm.SolutionView — Type
SolutionView(back, solution)

The solution of the last Solve.
